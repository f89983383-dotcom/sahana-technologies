PROJECT: SAHANA TECHNOLOGIES
FEATURE: AUTOMATIC PRODUCT IMAGE FINDER AND DOWNLOADER

I already have a Sahana Technologies computer-information website with approximately 75 products/components.

I want to add an AUTOMATIC PRODUCT IMAGE FINDING SYSTEM.

IMPORTANT:
This is NOT an e-commerce website.
The website is an educational/reference website for computer parts and approximate Sri Lankan market prices.

==================================================
MAIN GOAL
==================================================

I do NOT want to manually search Google Images, download every image, rename every file, and put every image into folders.

Create a build-time image-finding system that can:

1. Read all existing products from the website.
2. Automatically determine each product's name and category.
3. Search the web for a suitable product image.
4. Prefer official manufacturer/product pages and sources that permit reuse.
5. Download the selected image locally.
6. Save it into the correct product category folder.
7. Give the image a clean filename.
8. Automatically connect the downloaded image to the correct product card.
9. Never break the website if an image cannot be found.

==================================================
IMPORTANT COPYRIGHT / SOURCE RULES
==================================================

DO NOT simply scrape random Google Images.

Do not download images when their usage rights are clearly unsuitable.

Prefer:

1. Official manufacturer product pages
2. Manufacturer media/product assets where appropriate
3. Product images with clear reuse/redistribution permission
4. Other reliable sources where image usage is permitted

Use Google/Bing image search only as a discovery mechanism if legally and technically appropriate, not as a source to blindly scrape images.

Do not copy entire product pages.

Do not copy product descriptions.

Do not copy another company's website design.

Only obtain the minimum image needed for the product card.

Add a source/attribution record for every downloaded image when the source requires attribution.

==================================================
DO NOT USE RUNTIME SCRAPING
==================================================

The public website will eventually be hosted on GitHub Pages.

Therefore:

DO NOT make the browser scrape Google Images.

DO NOT require a backend for normal website operation.

DO NOT use runtime web scraping from JavaScript.

The image search/download system should run LOCALLY during development/build time.

After the images are downloaded, the website should work normally using local files.

==================================================
IMAGE SEARCH QUALITY
==================================================

The system must search using a precise product query.

For example:

"Intel Core i5-12400F official product image"

"AMD Ryzen 5 5600 official product image"

"NVIDIA RTX 4060 product image"

"Kingston Fury 16GB DDR4 product image"

Use brand + model whenever possible.

Do not select a visually similar but incorrect product.

For example:

DO NOT use an RTX 4070 image for an RTX 4060 product.

DO NOT use an i5-13400 image for an i5-12400F product.

The model must match.

==================================================
IMAGE VALIDATION
==================================================

Before saving an image:

- Check that the URL returns an actual image.
- Check HTTP status.
- Check Content-Type.
- Check file size.
- Check image dimensions.
- Reject tiny images.
- Reject obvious icons/logos when a product photo is available.
- Reject HTML pages saved as image files.
- Reject broken images.
- Reject unrelated images.

Prefer product images with:

- clear product visibility
- plain/clean background
- reasonable resolution
- correct product model
- minimal watermarks

Prefer approximately 500px or higher where available.

Do not download unnecessarily huge images.

Optimize images where appropriate.
